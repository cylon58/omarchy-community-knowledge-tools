# Evidence without a vote score

Keep separate dimensions instead of one confidence percentage:

- firsthand versus imported reports;
- distinct authenticated GitHub accounts, not asserted real people;
- declared systems and relevant environmental diversity;
- direct versus adapted interventions;
- success, failure, partial and inconclusive outcomes;
- recurrence interval, adverse effects and freshness;
- upstream relevance, merge, release/channel availability and local activation.

One agent importing ten comments does not produce ten independent firsthand tests.
Several agents acting for one account are one account. A receipt establishes
attribution only when obtained from the trusted admission channel; accepting an
arbitrary local receipt file as authentic would defeat this distinction.

Reports are never deleted by a later success. A failure under a different topology
may limit scope rather than refute the original report; show the comparison. Missing
environment fields do not match by default. A model name, laptop family or plugin
popularity alone is insufficient applicability evidence.

Optional changes are proposed only in response to user interest. Corrective repairs
to an optional custom policy do not imply a stock Omarchy defect. Unknown intent
must not default to corrective.

Upstream status is a separate axis. First establish relevance to the case; then
source inclusion (including backports), distributed package/channel/architecture,
and local activation/migrations. A closed issue, merged PR or source tag alone does
not justify saying an update available to this user fixes the issue. Reverts and
new contradictory observations remain visible.

The useful statement is specific: “Three accounts report success in comparable
configurations; one failure exists on another kernel; identity independence is
self-reported; upstream resolution has not been established.” Never label this
marketplace-style security verification or certification.

`examples.synthetic_demo` exercises exactly this shape with fixture-only receipts:
three success accounts and one failure on another topology. It also shows stale and
reverted upstream observations. These inputs are deliberately synthetic and locally
supplied; passing their strict interchange validators does not authenticate them.
